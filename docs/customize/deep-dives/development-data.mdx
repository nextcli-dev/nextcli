NextCLI can record development data — events about chats, edits and completions — for your own analysis. Nothing is sent to NextCLI's developers.

## Local dev data

Local dev-data logging is **off by default**. To turn it on, set the `NEXTCLI_TRACE` environment variable before starting VS Code:

| Value | What is written |
| --- | --- |
| unset | Nothing is written. The extension drops each event before validating it. |
| `basic` | Events without prompts, completions or file contents (the `noCode` schema level). |
| `full` | Events with the full content: prompts, completions and file text (the `all` level). |

Events are appended as JSON lines to `~/.continue/dev_data/0.2.0/<eventName>.jsonl`. An unknown value keeps logging off and prints one warning. Files written by earlier versions stay where they are; delete them yourself if you don't want them.

The chat panel still sends each model call's event, prompt included, to the extension when `NEXTCLI_TRACE` is unset; the extension discards it. Destinations in the [`data` block](#how-to-configure-custom-data-destinations) of `config.yaml` receive events whatever `NEXTCLI_TRACE` is set to, at the level each destination configures.

The same variable controls `cn`'s [model-call trace](/cli/configuration#logs-and-traces), so one setting works for both. `cn` currently treats `full` as `basic` for its trace.

On macOS and Linux, VS Code reads the login shell's environment at startup, so an `export NEXTCLI_TRACE=basic` in your shell profile works after a restart. On Windows, set it as a user environment variable.

<Warning>
  `full` records the exact prompts and file contents you work with. Keep those files private.
</Warning>

## Chat sessions

Saved chats in `~/.continue/sessions` keep each model call's completion, token usage and cost, but not the prompt sent to the model. That prompt is the whole conversation again, so storing it made long sessions grow to hundreds of MB and froze VS Code when switching chats.

To keep prompts, set `NEXTCLI_TRACE=full`: each call's prompt and completion are appended to `chatInteraction.jsonl` with the chat's `sessionId`. `chatFeedback` events from the thumbs buttons no longer include the prompt; match them to `chatInteraction` lines by `sessionId`.

Sessions saved by earlier versions drop their stored prompts the next time they are saved. To keep a copy, back up `~/.continue/sessions` before upgrading.

## How to Configure Custom Data Destinations

You can also configure custom destinations for your data, including remote HTTP endpoints and local file directories.

Data destinations should be configured directly in the `data` section of your `config.yaml` file. See more details about adding `data` configuration in the [YAML specification](/reference#data).

When sending development data to your own HTTP endpoint, it will receive an event JSON blob at the given `schema` version. You can view event names, schema versions, and fields [here in the source code](https://github.com/nextcli-dev/nextcli/tree/main/packages/config-yaml/src/schemas/data).
