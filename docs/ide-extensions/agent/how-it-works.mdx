## How the Tool Handshake Works

Tools provide a flexible, powerful way for models to interface with the external world. They are provided to the model as a JSON object with a name and an arguments schema. For example, a `read_file` tool with a `filepath` argument will give the model the ability to request the contents of a specific file.

The following handshake describes how Agent mode uses tools:

1. In Agent mode, available tools are sent along with `user` chat requests
2. The model can choose to include a tool call in its response
3. The user gives permission. This step is skipped if the policy for that tool is set to `Automatic`
4. NextCLI calls the tool using built-in functionality or the MCP server that offers that particular tool
5. NextCLI sends the result back to the model
6. The model responds, potentially with another tool call and step 2 begins again

<Info>
  Tool availability varies by mode: - **Chat mode**: No tools included - **Plan
  mode**: Only read-only tools included - **Agent mode**: All tools included
</Info>

## What Built-in Tools Are Available

NextCLI includes several built-in tools which provide the model access to IDE functionality.

### What Tools Are Available in Plan Mode (Read-Only)

In Plan mode, only these read-only tools are available:

- **Read file** (`read_file`)
- **Read currently open file** (`read_currently_open_file`)
- **List directory** (`ls`)
- **Glob search** (`glob_search`)
- **Grep search** (`grep_search`)
- **Fetch URL content** (`fetch_url_content`)
- **Search web** (`search_web`)
- **View diff** (`view_diff`)
- **View repo map** (`view_repo_map`)
- **View subdirectory** (`view_subdirectory`)
- **Codebase tool** (`codebase_tool`)
- **Ask question** (`ask_question`)

### What Tools Are Available in Agent Mode (All Tools)

In Agent mode, all tools are available including the read-only tools above plus:

- **Create new file** (`create_new_file`): Create a new file within the project
- **Edit file** (`edit_existing_file`): Make changes to existing files
- **Run terminal command** (`run_terminal_command`): Run commands from the workspace root. Commands run without secret-like environment variables (API keys, tokens, passwords), including ones your shell profile exports. List the ones a command needs in the `continue.terminalPassEnv` setting. Only your user settings count: a workspace's `.vscode/settings.json` can't change it.
- **Create Rule Block** (`create_rule_block`): Create a new rule block in `.continue/rules`
- All other write/execute tools for modifying the codebase

### Questions From the Agent

When a decision is yours to make, the model asks with `ask_question`: up to four questions, each with a few options. The questions replace the chat input until you answer.

- Click an option, or move with <kbd>↑</kbd>/<kbd>↓</kbd> and press <kbd>Enter</kbd> to pick it and go to the next question. Number keys pick an option directly.
- When more than one answer can apply, <kbd>Space</kbd> toggles an option and <kbd>Enter</kbd> moves on.
- Type to give your own answer in **Other**.
- <kbd>Esc</kbd> skips a question. The model then decides on its own and says what it assumed.
- The **×** button, or <kbd>Cmd</kbd>+<kbd>Backspace</kbd> (<kbd>Ctrl</kbd>+<kbd>Backspace</kbd> on Windows and Linux), dismisses all the questions and ends the turn, so you can answer in the chat.

The tool runs without asking for approval, in both Agent and Plan mode. To turn it off, set **Ask Question** to **Excluded** in the tool settings.
