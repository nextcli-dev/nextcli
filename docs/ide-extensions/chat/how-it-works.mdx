## How Chat Core Functionality Works

When you start a chat conversation, NextCLI:

1. **Gathers Context**: Uses any selected code sections and @-mentioned context
2. **Constructs Prompt**: Combines your input with relevant context
3. **Sends to Model**: Prompts the configured AI model for a response
4. **Streams Response**: Returns the AI response in real-time to the sidebar

## How Context Management Works

### What Context Is Automatically Included

- Selected code in your editor
- Current file context when relevant
- Previous conversation history in the session

### How to Add Manual Context

- `@Files` - Reference specific files

## How Response Handling Works

Each code section in the AI response includes action buttons:

- **Apply to current file** - Replace selected code
- **Insert at cursor** - Add code at cursor position
- **Copy** - Copy code to clipboard

## How Session Management Works

- Use `Cmd/Ctrl + L` to start a new session
- Clears all previous context for a fresh start
- Helpful for switching between different tasks

## Compact the Conversation

A long session fills the model's context window. Once it's full, the oldest messages are left out of each request. Compacting replaces the conversation up to a response with a summary, so later requests send the summary and the turns after it instead.

### Start a Compaction

- Click the compact icon (arrows pointing inward) under a response. It summarizes the conversation up to and including that response.
- Once the window is 60% full, or the oldest messages are already left out, the icon under the last response gets a **Compact conversation** label. A context ring also appears next to the input once the chat has history. Hover or click it for the breakdown, then choose **Compact now** or **View report**. The ring is amber at 80% of the pruning point and red once messages are pruned.
- A last response that ends with tool calls has no icon under it. Use the context ring, or the icon under an earlier response.
- You can't compact while a response streams or tools run, or while that response is already being summarized.

The selected chat model writes the summary. While it runs, the response shows "Generating conversation summary" and a **Cancel** link. You can switch to another session meanwhile: the summary is saved to the session it belongs to.

### What the Summary Includes

If an earlier response already has a summary, the latest one stands in for everything up to that response. The summary request then contains:

- that earlier summary;
- the messages after it, up to and including the response you chose, with their attached context, such as `@` files, and their tool calls and results.

Without an earlier summary, it contains every message up to that response. Compacting a response again replaces its summary, starting from the summary before it.

The request leaves out the agent's system prompt, your rules and the tool definitions, because it runs without tools.

If the request doesn't fit the model's window, the longest tool outputs are shortened until it does, and a notification says how many. If it still doesn't fit, compaction fails and the conversation is left as it is.

The summary appears under the response it covers. The latest one comes after a **Previous Conversation Compacted** divider, and the messages up to and including its response stay in the chat, dimmed. The context ring stays visible and shows an empty arc until the next request reports the new size.

### Cancel or Remove a Summary

- **Cancel** stops the summary. Nothing is saved.
- The trash icon on **Conversation Summary** removes that summary. Later requests then use the summary before it, if there is one, with the turns after it. With no summary left, they send the full conversation again. Removing the summary in use, without leaving the session that made it, brings back the context ring's measure from before it.
- If compaction fails, a notification gives the reason. If the response is deleted before the summary is saved, a notification says the summary wasn't saved. Deleting the session stops its compaction.

### See What Fills the Context

**View report** opens a page with two tabs.

**Context window** shows what the next request will carry:

- How full the window is, with the pruning point marked on the bar. A banner appears near the pruning point and once older messages are left out.
- The system prompt, tool definitions and conversation, largest parts first. Click a row to open it; long lists show the five largest with **Show all**. The conversation includes tool results, often its largest part. These counts are estimates.
- The largest tool results, with the response that made each call.
- How the pruning point is worked out: the model window, minus the space reserved for the reply, minus a safety buffer. When the model has no known window, the window is the 128,000 default.
- The estimate for the next request beside the provider's count for the last one. The two differ because the next request also carries the last response and any new tool output.

**Session usage** shows what each model used in the session: requests, input, cached and output tokens, and cost. The counts come from what the provider reported for each chat response. A response whose price isn't known shows no cost rather than $0, and a model running on your machine isn't priced. Compaction summaries and session titles aren't counted, and responses saved before this version have no cost.
