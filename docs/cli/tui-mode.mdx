Run `cn` to start an interactive session. You get a prompt where you can type messages, reference files with `@`, and use slash commands. `cn` uses the same underlying agent as the NextCLI IDE extensions.

## `@` Context

Use `@` to point the agent at specific files or directories:

```
> @src/auth/middleware.ts Why is this middleware rejecting valid tokens?
> @tests/ Write missing test cases for the auth module
> @package.json @tsconfig.json Help me set up path aliases
```

The agent reads the referenced files and uses them as context for its response.

## Slash Commands

Type `/` to see available commands. Run `/help` for the full list.

| Command | What it does |
|---------|-------------|
| `/help` | Show the help message and keyboard shortcuts |
| `/clear` | Clear the chat history |
| `/login` | Authenticate with your account |
| `/logout` | Sign out of your current session |
| `/update` | Update the NextCLI CLI |
| `/whoami` | Check who you're currently logged in as |
| `/info` | Show session information, including token usage and cost |
| `/model` | Switch between configured chat models |
| `/config` | Switch configuration or organization |
| `/mcp` | Manage MCP server connections |
| `/init` | Create or update the project's `AGENTS.md` |
| `/compact` | Summarize chat history into a compact form |
| `/resume` | Resume a previous chat session |
| `/fork` | Start a forked chat session from the current history |
| `/title` | Set the title for the current session |
| `/rename` | Rename the current session (alias for `/title`) |
| `/exit` | Exit the chat |
| `/jobs` | List background jobs |

When you're connected to a remote environment, NextCLI also adds remote-only slash commands such as `/diff` and `/apply`.

## Resume previous sessions

Pick up where you left off:

```bash
# Resume the most recent session
cn --resume

# Or use the slash command inside a session
> /resume
```

This restores the full conversation history, so the agent remembers prior context.

## Interactive questions in TUI mode

The agent can use the `AskQuestion` tool to gather clarifications before it continues. You will see a quiz-style prompt directly in the terminal.

- Use <kbd>↑</kbd>/<kbd>↓</kbd> to highlight an option
- Press <kbd>Enter</kbd> to submit the highlighted option
- Start typing to send a custom answer (even when options are shown)
- If a default answer is provided, pressing <kbd>Enter</kbd> on an empty input submits that default

This is useful when the agent needs decisions like scope, preferences, or environment details before making edits.

## Tool permissions

Tools that can change your system (file writes, shell commands, MCP tools) stop and ask before running:

```
Bash
Will run: npm test

Would you like to continue?

Note: Dangerous commands will be blocked regardless of your preference.

> Continue (tab)
  Continue + don't ask again (shift+tab)
  No, and tell NextCLI what to do differently (esc)
```

- **Continue** (Tab or `y`) approves this call.
- **Continue + don't ask again** (Shift+Tab) approves it and saves a rule to `~/.continue/permissions.yaml`, so the same command or tool runs without asking from now on. For a shell command the rule covers the command and its subcommand (`npm test` saves `Bash(npm test*)`); a chained or wrapped command is approved once and nothing is saved.
- **No, and tell NextCLI what to do differently** (Esc or `n`) rejects the call, stops the turn and lets you type new instructions. Ctrl+C does the same.

The note under a shell command means what it says: `rm -rf /` and the like never run, whatever you answer.

Read-only tools (`Read`, `List`, `Search`, `Diff`, `Fetch`, `AskQuestion`, `Checklist`, `Status`, `Skills`) run without asking. Shift+Tab outside a prompt cycles the [permission mode](/cli/modes): normal → plan (`⏸ plan`, never writes) → auto (`⏵⏵ auto`, nothing asks). See [tool permissions](/cli/tool-permissions) for the rules, the flags and `permissions.yaml`.
