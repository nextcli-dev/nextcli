Run `cn` to start an interactive session. You get a prompt where you can type messages, reference files with `@`, and use slash commands. `cn` uses the same underlying agent as the NextCLI IDE extensions.

## `@` Context

Use `@` to point the agent at specific files or directories:

```
> @src/auth/middleware.ts Why is this middleware rejecting valid tokens?
> @tests/ Write missing test cases for the auth module
> @package.json @tsconfig.json Help me set up path aliases
```

The agent reads the referenced files and uses them as context for its response.

## Slash Commands

Type `/` to see available commands. Run `/help` for the full list.

| Command | What it does |
|---------|-------------|
| `/help` | Show the help message and keyboard shortcuts |
| `/clear` | Clear the chat history |
| `/login` | Authenticate with your account |
| `/logout` | Sign out of your current session |
| `/update` | Update the NextCLI CLI |
| `/whoami` | Check who you're currently logged in as |
| `/info` | Show session information, including token usage and cost |
| `/model` | Switch between configured chat models |
| `/config` | Switch configuration or organization |
| `/mcp` | Manage MCP server connections |
| `/init` | Create `AGENTS.md`, or update the first agent file already in the working directory (`AGENTS.md`, `AGENT.md`, `CLAUDE.md`, `CODEX.md`) |
| `/compact` | Summarize chat history into a compact form |
| `/context` | Show what fills the context window: system prompt, tools, history, the largest tool results, and the compaction threshold |
| `/resume` | Resume a previous chat session |
| `/undo` | Undo the last turn: put its files back and remove it from the chat |
| `/redo` | Re-apply the turn you just undid |
| `/fork` | Start a forked chat session from the current history |
| `/title` | Set the title for the current session |
| `/rename` | Rename the current session (alias for `/title`) |
| `/exit` | Exit the chat |
| `/jobs` | List background jobs |

When you're connected to a remote environment, NextCLI also adds remote-only slash commands such as `/diff` and `/apply`.

## Context window

The status bar shows how full the model's context window is, for example `Context 23% · 46K/200K`: about 46K tokens used in a 200K window. The count covers the system prompt, the tool definitions and the chat history. It's the same estimate `cn` uses to decide when to compact the chat automatically. The bar turns amber at 80% of the compaction threshold.

When the history is compacted, automatically or with `/compact`, `cn` prints a divider, a notice that the history was compacted (with anything the summary had no room for), and the turns after it, below the earlier turns. Nothing on screen is cleared, so the earlier turns stay where they were. Editing a message or undoing a turn is different: it clears the screen and its scrollback and prints the conversation again.

`/context` prints the same estimate as a tree:

- Each row is labelled `estimated`, `measured` or `configured`.
- Tool results show the five largest.
- The threshold line is the window, minus the space reserved for the model's reply, minus a safety buffer.
- When the last response reported usage, the provider's numbers are labelled `measured`: prompt, output, cache read, cache write and the cache-hit ratio.

## Resume previous sessions

Pick up where you left off:

```bash
# Resume the most recent session
cn --resume

# Or use the slash command inside a session
> /resume
```

This restores the full conversation history, so the agent remembers prior context.

### Session transcripts

Next to each session's file, `~/.continue/sessions/<id>.jsonl` keeps a transcript of the session that only grows. Compaction and `/undo` shorten the session itself, never the transcript: compacted turns stay in it, and undone ones are marked rather than removed. It holds the full text of every turn, tool output included, and the VS Code extension writes the same file for its sessions. Deleting a session deletes its transcript.

## Undo a turn

Before each turn, `cn` records the state of your git work tree, so you can take back what the agent changed: edits, new files, and files that shell commands deleted or wrote.

- `/undo` shows the files it will put back, the files it will delete (the agent created them) and any file someone changed after the agent wrote it. For a turn that was interrupted, every file it touched is in that last list, because `cn` can't tell the agent's edits from later ones. Choose **Restore code and conversation** to also remove the turn from the chat (press <kbd>↑</kbd> to get the prompt back), or **Restore code only** to keep the chat.
- `/redo` re-applies what you undid. Sending a new message makes the undo final.
- To go back further, press <kbd>Esc</kbd> twice, select an earlier message and press <kbd>r</kbd>. Every turn from that message on is undone. <kbd>Enter</kbd> still edits the message without touching files.

Undo restores only the files the undone turns changed, so your own edits to other files stay. It works after `cn --resume` too. It doesn't undo:

- files outside the git repository
- files git ignores and untracked files over 2 MB, unless the agent wrote them with its file editing tools (shell commands that write them aren't covered)
- the contents of submodules, or which commit a submodule points to
- anything inside `.git`
- what a background job writes after the turn ends
- anything outside your files, such as commits, network calls or databases

Snapshots live in `~/.continue/snapshots`, one store per repository, and are deleted after 30 days. They need git 2.26 or later and a folder inside a git repository. They never run in `cn -p`, `cn review` or `cn serve`. Turn them off with `--no-snapshots` or `NEXTCLI_SNAPSHOTS=0`.

## Interactive questions in TUI mode

The agent can use the `AskQuestion` tool to ask you up to four questions before it continues. The questions replace the input line until you answer.

- Use <kbd>↑</kbd>/<kbd>↓</kbd> to highlight an option, and <kbd>Enter</kbd> to pick it and go to the next question. Number keys pick an option directly.
- When more than one answer can apply, the options show `[ ]`: <kbd>Space</kbd> toggles one and <kbd>Enter</kbd> moves on.
- Start typing to give your own answer in **Other**, alone or next to the options you picked.
- <kbd>←</kbd>/<kbd>→</kbd> move between questions without losing your answers.
- <kbd>Esc</kbd> skips a question. The agent then decides on its own and says what it assumed.
- <kbd>Ctrl</kbd>+<kbd>C</kbd> dismisses all the questions and ends the turn, so you can answer in your own words.

Only the main session asks: subagents can't, and `cn -p` doesn't offer the tool.

## Tool permissions

Tools that can change your system (file writes, shell commands, MCP tools) stop and ask before running:

```
Bash
Will run: npm test

Would you like to continue?

Note: Dangerous commands will be blocked regardless of your preference.

> Continue (tab)
  Continue + don't ask again (shift+tab)
  No, and tell NextCLI what to do differently (esc)
```

- **Continue** (Tab or `y`) approves this call.
- **Continue + don't ask again** (Shift+Tab) approves it and saves a rule to `~/.continue/permissions.yaml`, so the same command or tool runs without asking from now on. For a shell command the rule covers the command and its subcommand (`npm test` saves `Bash(npm test*)`). A chain saves one rule for each command not yet allowed (`git add -A && git commit -m x` saves `Bash(git add*)` and `Bash(git commit*)`). A wrapped command (`timeout 60 npm test`) or a line that writes a file (`npm test > out.txt`) is approved once and nothing is saved.
- **No, and tell NextCLI what to do differently** (Esc or `n`) rejects the call, stops the turn and lets you type new instructions. Ctrl+C does the same.

The note under a shell command means what it says: `rm -rf /` and the like never run, whatever you answer.

Read-only tools (`Read`, `List`, `Search`, `Diff`, `Fetch`, `AskQuestion`, `Checklist`, `Status`, `Skills`) run without asking. Shift+Tab outside a prompt cycles the [permission mode](/cli/modes): normal → plan (`⏸ plan`, never writes) → auto (`⏵⏵ auto`, nothing asks). See [tool permissions](/cli/tool-permissions) for the rules, the flags and `permissions.yaml`.
