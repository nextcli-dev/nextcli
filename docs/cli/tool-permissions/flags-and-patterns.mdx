## Flags

`--allow`, `--ask` and `--exclude` take a [tool matching pattern](#tool-matching-patterns) and can be repeated:

```bash
# Allow file writes without prompting
cn --allow Write --allow Edit

# Ask before fetching a URL, which runs without asking by default
cn --ask Fetch

# Remove the shell from a session
cn --exclude Bash

# Let a headless run fetch one site, or call one MCP server's tools
cn -p "Summarize the release notes at https://docs.example.com/releases" --allow "Fetch(https://docs.example.com/*)"
cn -p "Triage the open issues" --allow "github_*"

# Let a headless run run its tests and fix the code
cn -p "Fix the failing test" --allow "Bash(npm test*)" --allow Edit

# Allow everything (headless automation you trust)
cn -p "Set up the project" --allow "*"
```

What flags do:

- **Flags come before `permissions.yaml` and the defaults.** `--allow Edit` wins over an `exclude: [Edit]` saved in `permissions.yaml`.
- **Inside the flags, excludes come first, then asks, then allows,** whatever order you write them in. `--exclude Bash --allow "Bash(git log*)"` denies `git log`: the exclude for the whole tool matches first. To narrow a tool, exclude the pattern you don't want and let the default or a broader allow handle the rest: `--allow Bash --exclude "Bash(npm install*)"`.
- **An `--allow` is the operator's opt-in and is taken as given.** `cn -p --allow Bash` runs `curl` or `npm install`; only the commands that [never run](/cli/tool-permissions/read-only-commands#never-run) are still blocked. The exception is `--readonly`, which clamps every allow (see [Plan mode](/cli/modes/plan-mode)).
- **`--ask` in a headless run means refused,** and the tool isn't offered.
- **A pattern that can't work stops `cn` at startup** with a message that names the pattern: a pattern on a tool that has no argument to match (`--allow "github_create_issue(x)"`), an unclosed one (`--allow "Write(src"`), or an empty value.

## Tool matching patterns

The same syntax is used by the flags, by `permissions.yaml` and in the messages `cn` prints:

- `Write` matches every call to the `Write` tool. `Write()` and `Write(*)` mean the same.
- `Write(**/*.ts)` matches `Write` calls whose path matches the glob.
- `github_*` matches every tool whose name starts with `github_`. `*` matches any characters and `?` one character. Names are case-sensitive.
- `*` matches every tool.

An MCP tool keeps the name its server gives it, with no server prefix, so `github_*` covers a server whose tools are called `github_create_issue` and so on, and nothing on a server that calls the same tool `create_issue`. Check the names with `/mcp` in the TUI. To allow a whole server by name, list it in an [agent file](/cli/tool-permissions/agent-files) instead.

Only these tools take a pattern. It is matched against one argument:

| Tool | Argument the pattern matches |
|------|------------------------------|
| `Bash` | the command line |
| `Read`, `Write`, `Edit`, `MultiEdit`, `Diff` | the file path |
| `List` | the directory |
| `Fetch` | the URL |
| `Search` | the search pattern, not the files searched |

### File paths

A path pattern is matched the way the tool will use the path:

- A relative pattern is relative to the working directory; an absolute pattern works too. `*` matches within one directory and `**` any number of them: `src/*` covers `src/a.ts` but not `src/x/a.ts`; `src/**/*.ts` covers both. Dotfiles match, so `Read(.env*)` covers `.env.local`.
- The path is resolved first, so `./src/a.ts` and `/path/to/project/src/a.ts` match `src/*`, and `src/../.env` doesn't.
- Symlinks are followed. An `--allow` pattern must match both the path as written and the file it points to, so `Write(src/*)` doesn't cover a symlink in `src/` that points outside it. An `--exclude` or `--ask` pattern covers the call if either path matches.
- Matching is case-sensitive, even on a file system that isn't. `Read(.env*)` doesn't match `.ENV`.

```bash
# Allow writing TypeScript files anywhere, ask for everything else
cn --allow "Write(**/*.ts)" --allow "Edit(**/*.ts)"

# Keep the agent out of a file
cn --exclude "Read(.env*)" --exclude "Read(notes/secret*)"
```

### URLs

A `Fetch(...)` pattern is a plain glob over the URL as the model wrote it. `*` matches anything, including `/`:

```bash
# Fetch from one documentation site only
cn -p "What changed in v2?" --allow "Fetch(https://docs.example.com/*)"
```

`http://` and `https://` are different strings, and a redirect to another host isn't checked again. Prefer `Fetch(https://docs.example.com/*)` over a pattern with a bare host.

### Bash commands

A `Bash(...)` pattern is matched against the commands in the line, not the raw text, so quoting and spacing don't matter: `"npm" install` and `npm  install` match `Bash(npm install*)`.

An `--exclude` or `--ask` pattern errs toward matching. It covers the line if any command in it matches: after `&&`, `;` or a pipe; inside `$(...)`, `sh -c '...'`, `/bin/sh -c`, `bash -lc`, `eval` or `find -exec`; behind `env FOO=1`, `timeout 60`, `xargs`, `sudo`, `nice`, `nohup`, `builtin`, `busybox` and similar wrappers; glued to a flag (`bash -c'npm install x'`); or split across lines with a backslash. The command's directory is ignored (`/usr/bin/npm`, `./node_modules/.bin/npm`), and the pattern's other words only need to appear in order, so `Bash(npm install*)` also covers `npm -g install x` and `npm --prefix /tmp install x`. What an exclude can't see falls through to the next rule: `python -c '...'`, `bash script.sh` and `$CMD` aren't covered by `Bash(npm install*)`, so in a headless run the default decides them, and the default refuses them.

An `--allow` pattern errs toward not matching. It covers only a line that is one plain command, as written, with no `&&`, `;`, pipe, redirect or substitution. `Bash(npm test*)` allows `npm test` and `npm test -- --watch=false` but not `npm test; curl ...`, `npm test > out.txt`, `timeout 60 npm test` or `./npm test`. It never covers inline code or a variable command. A quoted operator inside an argument is part of that argument, so `Bash(grep*)` allows `grep "<div" index.html`. A script file named on the line is a command like any other: `Bash(python*)` allows `python x.py` whatever the script does.

```bash
# Allow bash, but never install packages
cn --allow Bash --exclude "Bash(npm install*)"

# Headless: run the tests, nothing else beyond the read-only defaults
cn -p "Make the tests pass" --allow "Bash(npm test*)" --allow Edit
```
