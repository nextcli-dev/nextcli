title: "Configuration"
---

`cn` resolves its configuration (models, MCP servers, rules, etc.) from several sources, in this order:

1. **`--config` flag** — a file path passed at launch
2. **Saved config** — the last-used configuration, persisted across sessions
3. **Default** — `~/.continue/config.yaml`

## `--config` flag

Point `cn` at a local YAML file:

```bash
cn --config ./my-config.yaml
```

This overrides any saved preference for the current session.

## Switching at runtime

Use `/config` inside a TUI session to switch between available configurations:

```
> /config
```

This shows your available local configs. The selection is saved for next time.

## Model settings

`/model` opens the model menu (experimental): the current model and its settings. Rows a model doesn't support are hidden.

| Setting | What it changes |
| --- | --- |
| Effort | Reasoning depth. Claude: `output_config.effort` (or a thinking budget on older models). OpenAI, OpenRouter and xAI: `reasoning_effort`. Gemini: `thinkingLevel` (a thinking budget on Gemini 2.5). |
| Thinking | `Off` turns thinking off, so no thinking tokens are used. `Hidden` lets the model think without showing the reasoning. `Shown` shows it dimmed above each reply. Modes a model can't use aren't listed, and the submenu title says why. |
| Fast | Claude Opus fast mode (`speed: "fast"`) or OpenAI priority processing. |
| Context | The context window `cn` plans for when it compacts the conversation. |

Which models can turn thinking off, and the effort levels each model takes, are listed in [Model settings](/ide-extensions/chat/model-settings). The CLI uses the same rules. On Bedrock, the CLI applies `Off` and the effort but doesn't turn thinking on yet. The VS Code extension does.

Settings are saved per model in `~/.continue/index/globalContext.json` and shared with the model menu in the VS Code extension. `cn` reads them when it starts, so a change made in VS Code applies from the next run.

For one run, including headless runs, pass `--effort`:

```bash
cn -p --effort low "Summarize the changes in this branch"
```

To set a default in `config.yaml`, use `reasoningEffort`. The flag and the menu take precedence over it:

```yaml
models:
  - name: Claude Opus 5.5
    provider: anthropic
    model: claude-opus-5-5
    apiKey: ${{ secrets.ANTHROPIC_API_KEY }}
    defaultCompletionOptions:
      reasoningEffort: high
```

## `config.yaml`

`cn` looks for `~/.continue/config.yaml`. This file uses the same format as the IDE extensions — see [config.yaml reference](/customize/deep-dives/configuration) for the full schema.

### OneProvider

`provider: oneprovider` uses one [OneProvider](https://oneprovider.dev) key for every model it serves. Claude models go through its Anthropic Messages API, so thinking, effort and fast mode work as they do with `provider: anthropic`. Other models go through its OpenAI-compatible API.

```yaml
models:
  - name: Claude Sonnet 5.5
    provider: oneprovider
    model: claude-sonnet-5-5
    apiKey: ${{ secrets.ONEPROVIDER_API_KEY }}
  - name: DeepSeek V4 Pro
    provider: oneprovider
    model: deepseek-v4-pro
    apiKey: ${{ secrets.ONEPROVIDER_API_KEY }}
```

Without a `config.yaml`, `cn` picks OneProvider up from `ONEPROVIDER_API_KEY` (or `ONEPROVIDER_KEY`). The VS Code extension doesn't support `provider: oneprovider` yet.

## CLI-specific flags

Several flags inject configuration at launch without editing a file:

```bash
# Add rules (file path or inline string)
cn --rule ./rules/style.md
cn --rule "Always use TypeScript strict mode"

# Load an agent file
cn --agent my-org/pr-reviewer
```

An agent file's `tools:` line replaces the default tool permissions for the session: listed tools run without asking and unlisted built-in tools are hidden. See [agent files](/cli/tool-permissions/agent-files).

All of these are repeatable — pass them multiple times to add multiple items.

## Secrets

Store sensitive values (API keys, tokens) as environment variables. Reference them in config with:

```yaml
${{ secrets.MY_API_KEY }}
```

## MCP servers that use OAuth

For a remote MCP server that requires OAuth, `cn` opens your browser to sign in the first time it connects. It saves the tokens in `~/.continue/mcp-oauth.json`. Headless runs (`cn -p`) reuse those tokens but never open a browser, so sign in interactively first or configure an `apiKey`. The browser redirects to port 33418; set `NEXTCLI_MCP_OAUTH_PORT` if that port is taken.

`cn` no longer starts `npx mcp-remote` for these servers. If you used a server through `mcp-remote` before, sign in to it once in an interactive session. See [OAuth-protected MCP servers](/customize/deep-dives/mcp#how-to-connect-to-oauth-protected-mcp-servers).

## Logs and traces

`cn` writes its log to `~/.continue/logs/cn.log`. The level sets how much goes there:

| Level | What it adds |
|-------|--------------|
| `error`, `warn` | Only problems |
| `info` | The default |
| `verbose` | One line per model call: tokens, cost, duration, finish reason, tool names |
| `debug` | Internals of the agent loop (same as `--verbose`) |
| `trace` | Every stream chunk. This is a lot of output |

Set it with `--log-level <level>`, or with `NEXTCLI_LOG_LEVEL` for every run. `--log-level` wins over `--verbose`, which wins over the environment variable. `cn review` passes the level on to its review workers.

For a machine-readable record of each model call, set `NEXTCLI_TRACE=basic`. Both variables are read when `cn` starts, and an unknown value prints a warning. `cn` then writes one JSON line per call to `~/.continue/traces/<sessionId>-<runId>.jsonl`, or to the folder in `NEXTCLI_TRACE_DIR`:

```json
{"ts":1762685578123,"dur":41000,"name":"llm.request","attrs":{"model":"deepseek-v4.1-flash","usage":{"prompt_tokens":25000,"completion_tokens":32000},"costUsd":0.046,"priced":"exact","finishReason":"length","ttftMs":900,"contentChars":0,"reasoningChars":90000,"toolCalls":[]}}
```

The first line is a header with the `cn` version, Node version, platform and ids. Each attempt sent to the provider is one line:

- `ttftMs` is the time to the first generated token, reasoning included.
- An attempt that streamed and then failed is written once, with `"discarded": true`, its `"error"` and what it produced up to then. A call that failed before streaming has `"error"` only.
- `"error"` is the provider's error message: its first line, at most 200 characters, with the HTTP `"status"` when there is one.

Apart from that error text, the trace holds token counts, timings and tool names, not prompt or file text. Tracing is off unless the variable is set.
