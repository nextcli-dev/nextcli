---
title: "Headless Mode"
---

Run `cn -p "your prompt"` to execute a single task without an interactive session. The agent runs to completion and prints its response to stdout.

```bash
cn -p "Generate a conventional commit message for the staged changes"
```

## Piping

Pipe data into `cn` to include it as context:

```bash
git diff --staged | cn -p "Write a commit message for this diff"
cat error.log | cn -p "Explain what went wrong"
curl -s https://api.example.com/health | cn -p "Is this healthy?"
```

Pipe the output into other tools:

```bash
cn -p "Generate a commit message" | git commit -F -
cn -p "List all TODO comments in src/" --silent > todos.txt
```

## Output options

| Flag | Effect |
|------|--------|
| `--silent` | Strip `<think>` tags and excess whitespace from output |
| `--format json` | Output structured JSON |

`--silent` is useful when piping output into another program. `--format json` is useful for parsing results programmatically.

## Tool permissions

Nobody is there to approve a tool, so a headless run is closed by default. With no flags it can read, search and list files, and run shell commands `cn` can tell are read-only (`ls`, `cat`, `grep`, `git status`, `git diff`, `git log`). File writes, `Fetch`, MCP tools and every other shell command are refused. Rules saved in the TUI with "don't ask again" don't apply; only the excludes in `permissions.yaml` do. Opt in to what a run needs with `--allow`:

```bash
# Fix code and run the tests, nothing else
cn -p "Fix the failing test in tests/auth.test.ts" --allow Edit --allow "Bash(npm test*)"

# Write only under docs/
cn -p "@src/api/ Document these endpoints in docs/api.md" --allow "Write(docs/**)" --allow "Edit(docs/**)"

# Fetch from one site
cn -p "Summarize https://docs.example.com/releases/v2" --allow "Fetch(https://docs.example.com/*)"

# Use one MCP server's tools
cn -p "Triage the open issues" --allow "github_*"

# Open the shell completely (run in a container for untrusted input)
cn -p "Set up the project and run the build" --allow Bash --allow Edit --allow Write

# Allow everything
cn -p "Set up the project" --allow "*"
```

<Warning>
Scripts that ran `cn -p` with Bash, `Fetch` or MCP tools and no flags need `--allow` for each of them now.
</Warning>

For untrusted input, such as a pull request in CI, add `--readonly`. It never writes, and `Bash` runs only read-only commands even when `--allow` turns it on: `cn -p --readonly --allow "Bash(git log*)"` adds `git log`, but `--allow Bash` or `--allow "Bash(git *)"` still can't run `git push`, `cp` or `curl`. `--allow Fetch` and `--allow "github_*"` work as in a normal run.

`cn -p --auto` is not "allow everything": it allows writes, `Fetch` and MCP tools, but `Bash` stays read-only and auto mode ignores `--allow`. Use `--allow "*"` instead.

When the model calls a tool the rules refuse, the call gets the result `Blocked by security policy: this tool call isn't allowed in an unattended run`, the run ends, and `cn` prints the answer so far. If a script needs that tool, pass the `--allow` for it.

`cn review` runs its workers headless with the same closed defaults plus `Edit`, `MultiEdit` and `Write`, so a review can fix the files in its worktree.

See [tool permissions](/cli/tool-permissions) for the rule syntax, the list of read-only commands, agent files and the full precedence.

## Resume in headless mode

Resume a previous session without interactive input:

```bash
cn -p --resume
```

This replays the previous session's history, which can be useful for inspecting past results in automation.

## Examples

```bash
# Git hooks
cn -p "Review staged changes for obvious bugs" --silent

# CI pipeline — review a pull request without touching it
cn -p "Review the diff against main for bugs" --readonly --silent > review.md

# CI pipeline — auto-fix lint errors in src/ and verify
cn -p "Fix all ESLint errors in src/" --allow "Edit(src/**)" --allow "Write(src/**)" --allow "Bash(npx eslint*)"

# Generate docs from code
cn -p "@src/api/ Generate OpenAPI documentation for these endpoints" --silent > api-docs.yaml

# Use a specific assistant
cn -p "Triage this error log" --config ./agents/error-triage.yaml
```
