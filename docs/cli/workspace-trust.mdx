---
title: "Workspace Trust"
---

`cn` loads environment variables from a folder's `.env` and `.continue/.env` only if you trust that folder. The first time you start an interactive `cn` session in a folder that has one of these files, it asks:

```text
Trust /Users/you/code/api? Its .env and .continue/.env, and those of folders inside it, can set cn's environment, including its model endpoint and keys. [y/N]
```

The answer is saved in `~/.continue/trusted-folders.json` and applies to that folder and everything under it. `cn` doesn't ask again. Trusting `~/code` trusts every repository in it.

A repository you didn't write, such as a pull request's checkout or a project you just cloned, can contain a `.env`. Trust decides whether that file may set `cn`'s environment: which provider keys and model `cn` uses, and which endpoint its model requests go to. Variables that would run code or redirect `cn` itself, such as `NODE_OPTIONS` or `GIT_CONFIG_*`, are never taken from a `.env` file, trusted or not (listed below).

## Trust or untrust a folder

```bash
cn trust              # this folder
cn trust ~/code/api   # another folder
cn trust --list       # every saved decision
cn untrust            # stop trusting this folder, even if a parent folder is trusted
```

## Headless runs

`cn -p`, `cn review`, `cn serve` and every other subcommand never ask. In a folder without a saved decision they don't load the project's `.env`, and `cn` prints one line on stderr saying so. A folder you trusted earlier loads as usual.

To trust the folder for a single run, pass `--trust-workspace` or set `NEXTCLI_TRUST_WORKSPACE=1`:

```bash
cn -p --trust-workspace "Run the integration tests and summarize the failures"
```

<Warning>
Don't pass `--trust-workspace` when `cn` runs on code you haven't read, such as a pull request in CI. The pull request's `.env` would then set `cn`'s environment.
</Warning>

## What a `.env` file can't set

These variables are never taken from a `.env` file, even in a trusted folder, because they change how processes start, where network traffic goes or where `cn` keeps its configuration. Set them in your shell or CI environment instead.

| Variables | What they control |
| --- | --- |
| `NODE_OPTIONS`, `NODE_PATH`, `NODE_EXTRA_CA_CERTS`, `NODE_TLS_REJECT_UNAUTHORIZED` | Node code and certificate checks for `cn` and its child processes |
| `SSL_CERT_FILE`, `SSL_CERT_DIR`, `CURL_CA_BUNDLE`, `REQUESTS_CA_BUNDLE` | Which certificates OpenSSL, curl and Python trust in the commands `cn` runs |
| `npm_config_*` (any case) | npm settings, including the registry `cn` updates itself from |
| `LD_*`, `DYLD_*`, `PATH`, `SHELL` | Which programs run |
| `BASH_ENV`, `ENV`, `ZDOTDIR`, `SHELLOPTS`, `BASHOPTS`, `PS4`, `PROMPT_COMMAND` | Shell startup files and options that run code |
| `HOME`, `USERPROFILE`, `HOMEDRIVE`, `HOMEPATH`, `XDG_CONFIG_HOME` | Where per-user configuration, such as git's and npm's, is read from |
| `GIT_*` | git configuration for the `git` commands `cn` runs |
| `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY` (any case) | Where model requests, which carry your API key, are sent |
| `CONTINUE_GLOBAL_DIR` | Where `cn` reads its config, permissions and trust decisions |
| `NEXTCLI_TRUST_WORKSPACE`, `NEXTCLI_VERSION_INFO_URL`, `NEXTCLI_API_BASE`, `OTEL_*`, `CONTINUE_CLI_ENABLE_TELEMETRY`, `CONTINUE_METRICS_ENABLED` | Trust, update checks, the API endpoint and telemetry |

Run with `--verbose` to see which names were skipped, in `~/.continue/logs/cn.log`.

## Keys for every folder

`~/.continue/.env` loads in every folder, trusted or not, with the same variables left out. Put provider keys there rather than in each repository. Started in your home folder, `cn` treats it as this file, not as the folder's `.continue/.env`, so it doesn't ask you to trust your whole home folder.

```bash
# ~/.continue/.env
ANTHROPIC_API_KEY=sk-ant-...
```

Variables already set in your environment take precedence over every file. A trusted folder's `.continue/.env` comes next, then its `.env`, then `~/.continue/.env`.

## Other files that follow trust

Secrets referenced as `${{ secrets.NAME }}` in your config come from the environment, which `~/.continue/.env` and, in a trusted folder, the folder's `.env` and `.continue/.env` feed. The variables listed above can't come from any of these files. `AGENTS.md`, rules and skills in the repository are read in every folder: they are instructions for the model, not configuration for `cn`.
